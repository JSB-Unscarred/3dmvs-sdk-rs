# M5 原生契约证据与残余假设

状态：已知限制登记  
适用基线：LPSDK `1.3.3.3`，`x86_64-pc-windows-msvc`  
结论：本项目当前无法取得下列事项的独立厂商书面保证

## 1. 证据边界

本项目可以证明 Rust 包装层在其声明的 Driver 契约下如何校验、复制、撤销和清理；不能从
闭源 SDK 的一次或长期正常运行证明该 Driver 契约永远成立。证据按强度分为：

1. **厂商明确说明**：公开头文件或开发指南直接定义的类型、参数或行为；
2. **厂商样例观察**：官方样例展示的调用方式，只能说明样例采用该模式；
3. **安装环境佐证**：DLL、导出、配置、版本和哈希的本机观察；
4. **工业实验观察**：特定设备、固件、网络、负载和时长下未观察到问题；
5. **包装层证明**：fake backend、ABI 断言、compile-fail、auto-trait 和 Miri 对 Rust 代码的验证。

只有第一类且内容直接覆盖问题时才能称为厂商保证。第二至第五类可以提高对特定实现的信心，
但不能替代厂商对缓冲区稳定、并发、回调排空、输入保留或后台任务终止的承诺。

## 2. 已知假设账本

| 区域 | 包装层依赖的原生假设 | 当前证据 | Rust 侧缓解 | 仍无法证明的风险 |
| --- | --- | --- | --- | --- |
| pull `GetImage` | 成功返回后，在没有插入其他 SDK 调用的立即同步复制期间，描述符与全部非空载荷可读且不被并发修改 | 公开字段定义、官方样例不分配/释放输出、运行时缓存配置 | 全局锁内完整校验、fallible allocation、立即复制，不导出裸指针 | SDK 私有线程可能在复制期间重写同一缓冲区 |
| 图像 callback | trampoline 返回前，描述符与报告的载荷保持可读且不被并发修改 | 样例在 callback 内检查/复制；无单独稳定窗口说明 | catch-unwind、长度与指针校验、立即拥有化、用户闭包移到 Rust 工作线程 | SDK 可能在 callback 尚未返回时并发修改载荷 |
| callback 生命周期 | Stop/Close 后可能仍有晚到或并发 callback，且没有已文档化 unregister | 头文件无注销接口，样例只展示注册流程 | 永不复用 cookie、registry 先撤销、引用计数排空、未知/晚到 cookie 忽略 | SDK 对 payload 本身的并发写入；原生内部资源何时释放 |
| 文件传输 | 成功 Close 会终止后台文件访问；`0/0` 不是完成；`completed == total > 0` 表示完成 | 头文件、进度接口与环境观察，没有完整生命周期说明 | 文件名由 Camera 保留；不把错误/倒退当终态；Close 不确定时有意泄漏小字符串 | SDK 在 Close 后继续解引用文件名，或使用不同完成语义 |
| ImgProc 输出 | 成功调用返回的 SDK 输出在立即复制期间可读，下一次算法调用前有效 | 官方样例、重复调用观察到内部地址复用 | 全局锁内校验并立即复制，限制总大小和输入张数 | SDK 私有线程异步改写输出或实际保留期更短 |
| ImgProc/Save 输入 | 标为 `[IN]` 的可变 C 指针实际只读，调用返回后不保留地址 | 参数标注和同步样例；没有明确“不写/不保留”保证 | 只传借用数据，校验紧密布局，调用期间保持存活 | SDK 写入 Rust 共享切片或在返回后继续使用地址 |
| Display | 图像数据与 Win32 句柄只在同步调用期间借用 | API 形态与观察；没有明确保留期说明 | `raw-window-handle` 借用，调用期间保持图像与窗口存活 | SDK 返回后异步绘制并继续使用地址或句柄 |

详细原始决策分别见：

- `m2/image-ownership-contract.md`；
- `m3/contracts.md`；
- `m4/callback-contract.md`；
- `m0/sdk-baseline.json` 与 `m0/api-contracts.json`。

## 3. 工业实验的用途与限制

工业实验可用于发现可复现问题、比较版本、验证安装步骤和建立运行告警，但实验通过只能形成
如下结论：

> 在所记录的设备、固件、LPSDK、操作系统、负载、网络和运行时长下，没有观察到指定失败。

它不能形成以下结论：

- 厂商保证缓冲区在复制期间稳定；
- Stop 或 Close 保证排空所有 callback 或后台文件线程；
- SDK 永远不写入 `[IN]` 指针或保留输入地址；
- 所有调度、设备、固件、CPU 架构和未来补丁版本行为相同；
- fake backend、Miri 或 Rust 数据竞争检测覆盖了 DLL 内部线程。

每次实验至少记录：

- 仓库 commit、crate 版本和 feature；
- `m0/sdk-baseline.json` 中相关文件的实际版本与 SHA-256；
- Windows 版本、MSVC/Rust 版本、设备型号、序列号脱敏标识和固件；
- 网络拓扑、触发模式、图像格式、帧率、队列容量、文件大小和算法输入；
- 开始/结束时间、总调用数、超时、断连、丢帧、callback 统计和清理日志；
- 是否注入断网、队列满、Stop/Close 竞争、进程退出和重复任务；
- 原始日志保存位置、负责人和复核人。

建议实验包含 pull 长时间采集、callback 并发与 Stop/Close 竞争、断网恢复、文件上传下载、
所有 ImgProc 路径和 Display 关闭窗口竞争。实验程序不得把厂商 DLL、LIB、头文件或安装包
复制进仓库或公开 CI artifact。

## 4. 发布措辞

允许的表述：

- “针对 LPSDK 1.3.3.3 与 x64 Windows MSVC 建立审计基线”；
- “包装层在返回 safe Rust 值前立即复制 SDK 输出”；
- “实机实验在已记录环境中未观察到某问题”；
- “该行为是实现所依赖、但未取得厂商书面确认的假设”。

禁止的表述：

- “厂商保证 callback/pull 缓冲区稳定”，除非取得可引用的新文件；
- “Miri 证明 FFI 安全”；
- “经过工业验证所以不会出现数据竞争”；
- “兼容 LPSDK 1.3.x/未来版本”；
- “可安全用于所有生产环境”。

README、API 文档、CHANGELOG 和 GitHub/crates.io 发布说明必须使用同一证据等级。营销性摘要
不能省略精确 SDK 版本、唯一原生 target 和残余假设链接。

## 5. SDK 更新与反证

以下任一变化都使既有原生证据失效，必须建立新基线：

- `MV3D_LP_GetVersion` 不再精确返回 `1.3.3.3`；
- 头文件、导入库、DLL、运行时配置或基础运行时哈希变化；
- 设备固件或官方文档改变相关生命周期说明；
- ABI 探针、fake backend 契约测试或实机日志出现与假设不一致的结果；
- 新增任何跨 FFI 借用、callback 类型或后台任务。

发现反证时，先停止发布并最小化受影响 surface。不得通过放宽测试、删除快照或只更新文字
接受漂移；修复应重新审计所有权、状态机和 Drop 顺序，并在 SECURITY/CHANGELOG 中披露影响。

## 6. 风险接受记录

在无法取得厂商保证的前提下，任何 native 预发布或正式发布都应填写。缺少厂商保证本身
是非阻塞已知假设；遗漏披露、遗漏具名复核，或已有证据与所需假设冲突才会阻塞发布：

```text
候选版本/commit：
精确 LPSDK 与文件哈希：
仍被接受的假设条目：
受影响的公开 API：
已完成的包装层门禁：
已完成的工业实验及其环境：
未完成或失败的证据任务：
选择（接受为非阻塞已知假设/移除/重设计/阻止发布）：
项目负责人、日期：
独立复核人、日期：
```

“接受为非阻塞已知假设”只代表项目负责人接受披露后的残余风险，不代表厂商确认，也不改变
safe Rust API 在内存安全方面应承担的审查标准。任何反证仍会立即把相关 surface 变成发布阻塞项。
