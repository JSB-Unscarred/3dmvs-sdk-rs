# 文件上传与下载

```mermaid
sequenceDiagram
    autonumber
    actor App as 业务代码
    participant Public as mv3d-lp 公共 API
    participant Core as mv3d-lp-internal
    participant Native as 厂商 LPSDK

    App->>Public: device.download_file(...) 或 upload_file(...)
    Public->>Core: Device::begin_file_transfer(names)
    Core->>Core: 构造调用期 descriptor 与 CString
    alt 下载 DeviceToHost
        Core->>Native: MV3D_LP_FileAccessRead(handle, names)
    else 上传 HostToDevice
        Core->>Native: MV3D_LP_FileAccessWrite(handle, names)
    end
    Native-->>Core: status
    alt 启动成功
        Core->>Core: state = Transferring
        Core-->>Public: Ok
        Public-->>App: Ok
    else 启动失败
        Core->>Core: state = Open
        Core-->>Public: Err
        Public-->>App: Err
    end

    App->>Public: device.file_transfer_progress()
    Public->>Core: Device::file_transfer_progress()
    Core->>Native: MV3D_LP_GetFileAccessProgress(handle)
    Native-->>Core: status + completed, total
    alt 查询成功
        Core->>Core: 校验非负且 completed 不大于 total
        alt total > 0 且 completed = total
            Core->>Core: state = Open
            Core-->>Public: Completed(progress)
            Public-->>App: 完成进度
        else 仍在传输（包括 0, 0）
            Core-->>Public: Running(progress)
            Public-->>App: 运行进度
            Note over App,Core: 调用方自行选择轮询、backoff 或 async 调度
        end
    else 查询失败
        Core-->>Public: Err
        Public-->>App: Err
        Note over App,Core: Device 仍为 Transferring，可重试查询
    end
```

头文件把 `MV3D_LP_FILE_ACCESS` 标为 `[IN]`，wrapper 因此只在 Read/Write 调用期间借用 descriptor 与两段字符串。调用成功才进入 `Transferring`，失败时仍为 `Open`。若厂商另有异步借用要求，需要重新审计该边界。`file_transfer_progress()` 只查询一次；调用方自行安排轮询、backoff 或 async。当前以 `total > 0 && completed == total` 判定完成，`(0, 0)` 仍按 Running 处理。

## 待确认厂商契约

- `(completed, total) == (0, 0)` 表示未开始、进行中、空文件还是完成。
