# 文件上传与下载

```mermaid
sequenceDiagram
    autonumber
    actor App as 业务代码
    participant Public as mv3d-lp 公共 API
    participant Device as internal Device
    participant Native as 厂商 LPSDK

    App->>Public: device.download_file(...) 或 upload_file(...)
    Public->>Device: begin_file_transfer(names)
    Device->>Device: 构造 descriptor 与两段 CString
    alt 下载 DeviceToHost
        Device->>Native: MV3D_LP_FileAccessRead(handle, descriptor)
    else 上传 HostToDevice
        Device->>Native: MV3D_LP_FileAccessWrite(handle, descriptor)
    end
    Native-->>Device: status
    alt 启动成功
        Device->>Device: 将本次两段 CString 追加到 backing 集合
        Device-->>Public: Ok
        Public-->>App: Ok
    else 启动失败
        Device->>Device: 丢弃本次 CString，既有 backing 集合不变
        Device-->>Public: Err
        Public-->>App: Err
    end

    loop 由调用方决定查询时机
        App->>Public: device.file_transfer_progress()
        Public->>Device: file_transfer_progress()
        Device->>Native: MV3D_LP_GetFileAccessProgress(handle)
        Native-->>Device: status + signed completed, total
        alt 查询成功
            Device-->>Public: FileProgress { completed: i64, total: i64 }
            Public-->>App: 原始进度快照
        else 查询失败
            Device-->>Public: Err
            Public-->>App: Err
        end
    end

    App->>Public: device.close() 或 drop(device)
    Public->>Device: cleanup
    Device->>Native: MV3D_LP_CloseDevice(handle) 一次
    Native-->>Device: status
    alt Close 成功
        Note over Device,Native: FileAccess 已停止引用文件名
        Device->>Device: 统一释放全部成功调用的 name pair
        Device-->>Public: Ok 或此前的 Stop error
        Public-->>App: Result
    else Close 失败
        Device->>Device: forget 全部 name pair，finalize_blocked = true
        Device-->>Public: 原始 Close error 或 Stop + Close 双错误
        Public-->>App: Err；结束进程
    end
```

`MV3D_LP_FILE_ACCESS` 的两个字段是裸 `const char*`。头文件的 `[IN]` 只表示参数方向，未说明异步传输是否继续持有字符串，也未确认下一次成功 FileAccess 会终止对旧文件名的引用。wrapper 因此追加保存每次成功 Read/Write 的两段 CString，至少保活到 Close；失败调用不保存本次 CString，也不改变既有集合。Close 成功后统一释放；Close 失败时 native 引用状态未知，整个集合封存至进程退出，同时阻止 Finalize。

FileAccess 不引入 wrapper 状态，重复启动、与采集并行以及查询时机均直接交给 SDK 判断。`file_transfer_progress()` 只复制一次 `MV3D_LP_FILE_ACCESS_PROGRESS`，保留厂商返回的 signed `completed` 与 `total`；库不校验非负、不比较两者，也不定义 Running 或 Completed。轮询、backoff、async 调度和完成判定由调用方负责。

## 待确认厂商契约

- FileAccess 启动返回后是否已复制文件名；若确认复制，可删除 `Device` 中的 backing 集合。
- signed `completed`、`total` 以及 `(0, 0)` 的完成语义。
